# Калибровка масштаба по измерениям

`calibrate_sensitivity.py` оценивает изменение коэффициента масштаба между двумя **измеренными** режимами чувствительности. Он не двигает мышь, не снимает данные, не меняет файлы настроек и не гарантирует работоспособность при неизвестной чувствительности.

## Какие данные нужны

Две серии: ранее настроенный режим и новый режим. В каждой — минимум пять отдельных импульсов на ось X и Y. Для каждого импульса нужны знаковое количество **фактически применённых** счётчиков и знаковое изменение координаты одной и той же неподвижной цели на экране после полного прохождения импульса. До и после импульса не должно быть других команд, перемещения физической мыши или движения цели. Масштаб интерфейса, разрешение, положение камеры, FOV, зум, DPI и прочие влияющие условия должны быть стабильными внутри серии.

Обычная трасса F10 записывает попытки отправки, а не подтверждение приёма HID, и при непрерывном трекинге команды перекрываются. Существующие игровые записи сами по себе не являются подходящими калибровочными импульсами. Для получения подходящих измерений нужна отдельная проверенная процедура изолированных импульсов, которой в этом пакете пока нет.

Каждый входной JSON имеет поля `x` и `y`, в каждом массив объектов с числовыми `counts` и `delta_px`. Значение `counts` — подписанные счётчики конкретного импульса; `delta_px` — подписанная разность координаты цели на экране после и до него. Для каждой оси нужно не менее пяти записей; абсолютные значения каждого импульса должны быть не менее 4 счётчиков и 1 пикселя. Диапазон каждого измерения ограничен одним миллионом по модулю. Знак отношения `delta_px / counts` должен быть согласован внутри и между сериями.

## Запуск

```text
python Source\tools\calibrate_sensitivity.py reference.json current.json --reference-scale 1.28 --output Evidence\calibration.json
```

`--reference-scale` должен быть фактическим `trackingOutputScale` старого профиля; `1.28` в команде — значение из обсуждённых логов, а не универсальный коэффициент. Укажите фактический результат и новое имя выходного файла: существующий файл утилита не перезапишет.

Она вычисляет медианы абсолютных отношений пикселей к счётчику отдельно по осям и предлагает новый масштаб по отношению старого отклика к новому. При заметно разном соотношении осей, большом разбросе или выходе за диапазон контроллера 0.05–2.0 предложение блокируется. Такие пороги — консервативные критерии проверки, а не доказательство точности. Перед применением проверьте результаты на малых движениях и остановите тест при резких скачках.

Формула предполагает приблизительно линейный отклик. Она не компенсирует изменённый зум/FOV, разное усиление осей, ускорение, задержку, квантование, движение цели или неизвестные команды; ручная помощь мышью также делает замер неоднозначным. Потребуются отдельные серии для разных режимов, например обычного обзора и прицеливания.
